# B3 规划任务与选择题契约

本文是活动 B3 规范，与 docs/blueprint/13_PLANNING_WORKBENCH.md 和共享契约共同约束正式实现。2026-10-04 已撤销单 Agent、单主要调用、后台评审禁令、旧多题预算与短时强制超时。旧实验规范见 history/12_B3_LEGACY_DISCOVERY.md，不作为生产回退。

## 任务与权威

正式运行入口为 PlanningRuntime。一个操作可以创建多个登记的 agy 任务；设计、研究、整合、独立评审、验证和修订各自记录输入、模型、调用、结果与错误。默认四并发，没有费用、Token、总调用次数或总修订轮数门禁。工作者不得编辑正式状态或启动未登记子 Agent。

状态只使用合法终态 structured_output，经共享 PLANNING_TASK_SCHEMA 与 Core 确定性验证后成为草案。AI 产物不能直接成为正式事实；结构化选项答案、用户手动编辑与 ChangeSet 批准才可以建立用户授权。

活动 JSON 由 packages/contracts/src/planning-schema.ts 生成。运行 pnpm schema:sync 更新 experiments/agent-benchmark/schemas/b3-discovery.schema.json，pnpm schema:check 和 tests/planning-schema.test.ts 防止漂移。legacy-b3-discovery.schema.json 只用于历史读取与兼容测试。

研究、验证与评审使用派生的职责 Schema：`groups=[]`、`questions=[]`、`clarification=null`，评审还要求 `followUp=[]`。只有已登记的 `decomposition` 任务可以返回非空 `workItems`；澄清、设计、整合、修订及支持角色的实际调用 Schema 和接收校验均要求该字段省略或为空，不通过删除非法字段采纳结果。这些支持任务提供证据和具体阻塞，由设计或修订任务形成变更。尚未开发的目标应用测量、不可用的容器或不适用的平台不能当作当前可执行试验；记录未执行，转成有实施前置和失败处理的开发验证任务。

### 单次输出容量与登记分工

实际服务输出超限才触发 `decomposition`，不设置本地数值 Token 预算。失败终态的非空输出也不能采纳。拆分任务仅返回 `workItems`，每项登记稳定块 ID 的独占范围、目标和依赖；新增、待修改与待删除内容都须有唯一所有者。范围重叠、循环、越界写入和必需内容遗漏不得进入交付。

全部合法片段以本地确定性操作完整汇集，再由独立评审检查。汇集结果不是一次 Provider 成功调用，其 `origin=assembly` 收据记录全部源任务及哈希、原候选依据和最终哈希；日志保留真实失败、拆分及各片独立调用。恢复必须重新核对合法来源，不能从 ERROR 输出或自然语言重建。单并发拆分不占用父任务的 Provider 槽。

分片不能作为完整最新草案使用。待修改或删除职责只能由候选中的实际替换或删除动作履行，旧正式块仍存在不能表示已完成。需要用户选择时保留暂缺范围和合法候选参考，回答后继续；超过三题保留后续队列，逐批通过 Core 校验，合法 `reopenReason` 不因主题曾回答而消失。

已完成且被明确登记为前置的分片正文进入后续分片上下文。当前待修问题与历史观察分别保存；修订任务通过 `repairIssues` 和 `repairSourceTaskId` 记录实际修复依据，不递归复制父任务所有旧问题。确定性检查通过后，最新独立评审裁定旧工作者阻塞是否仍成立；真实缺失来源、职责遗漏、依赖循环和审批前提仍由本地检查阻断。

删除分组中的部分区块只保留实际审批依赖，不把整组所有前置转移给删除任务。汇集 v2 对冻结 Core 证据和工作者证据做确定性身份隔离，候选不同解释使用派生 ID 并重写对应引用；正式证据原文不变，未引用的基准证据不进入当前候选。冻结证据文件及哈希属于恢复收据。历史 v0/v1 按原算法与字节验证，不重写。

恢复先校验登记与收据来源，再更新任何运行字段。登记为 assembly、已有分片或汇集依据的任务不能降格为 provider；来源不一致、未知来源及 v2 收据来源缺失返回 `RESULT_MODIFIED`。旧无来源收据仅在没有 v2 登记时允许按既存汇集依据推导，随后执行对应完整复核。

每个登记范围的全部 `blockIds` 都是必需候选职责，包括正式蓝图已有的 ID；初次设计没有原候选时也适用。恢复旧任务须重新核对该范围，不能依据旧的豁免列表或 `completed` 标记跳过遗漏。原结果和收据保留为诊断，失责片及依赖它的派生产物不能复用。

普通非澄清修订同样登记本 Run 之前待批准候选的完整范围。合法局部输出保留原结果与回执；缺失 ID 触发确定性自动修订，补齐后才评审或提案。明确删除履行该 ID 的职责，合法问题可以先暂停。新反馈 Run 不复制整套正式蓝图作为必需范围。`currentDraft` 是最新原始候选，可能局部；`unfinishedScopes` 按缺失 ID 提供本 Run 最近合法完成的真实候选或删除动作及精确任务来源，不能用最早完整稿遮掉后来已修好的内容。

任务上下文按实际传出的候选和依赖省略同 ID 正式旧正文，以免旧内容覆盖新修订；未改正式块仍完整传入，`blueprintContext.shadowedApprovedBlocks` 保留旧块锁定和批准来源。此为只读上下文投影，不构造新的正式蓝图，不改 `basis.json`、原产物或回执。待批准、替换/删除冲突和 Locked 规则继续有效；完整前值仍在 Core、审批预览与冻结依据中。

## 选择题

每轮最多三题，每题一个决策，稳定唯一 decisionKey；直接及间接依赖不能在同批冲突。二至四个真实选项包含 key、label、approach、gain、sacrifice、impact、reversibility，说明具体做法、收益、代价、实际影响和可逆性。推荐键必须存在，reason 与 recommendationReason 说明为什么现在问与推荐依据。默认单选，独立可组合能力允许多选，不预选或自动提交。

明确选择可以本地确认；custom 原文、delegate 和 defer 保存为待解释输入，不直接确认。delegate/defer 可以不填写补充文字。材料已经回答的事项不得再次询问；重问需说明 reopenReason。Core 不用通用题替代失败的 AI 题目，不合格问题交给登记修订任务。无法推进则明确暂停。

## 阶段与审阅

clarify 只返回理解摘要、内容依据与必要问题。目标、问题、预期结果、范围和约束明确表达或明确委托后，才允许 product。准备条件不使用关键词命中、条数或百分比。

product 交付产品与体验；批准后才能 technical；批准技术后才能 delivery。每阶段形成按主题组织的 ChangeSet，展示新增、替换、删除与影响。部分批准必须通过依赖与锁检查。feedback 依据已有方案和真实反馈局部修订，保留无关内容与稳定 ID，不宣称检查过未提供代码。

反馈明确要改变已有行为时，AI 直接提出受影响区块和 `decisions.replaces` 的待批准替代包，不因“原文不是直接批准”重复要求用户选择同一变更。该声明约束正式提交，不能阻止生成草案。评审核对替代内容与反馈一致；只有反馈本身尚有重大未决取舍才提问，Locked 内容仍需明确解锁后批准。

## 停止、取消与恢复

### 完整上下文读取

登记任务的全文输入按调用冻结，记录 SHA-256；CLI 首条输入仅传结构索引，通过 `planning_context` 的 `index`／`read` 按 JSON Pointer 条目分页读取完整内容。每页返回 offset、nextOffset、完整字符数与条目哈希；分页不限制总读取量，也不删减材料或方案。上下文是原需求及草案参考，不产生新证据或批准。

长方案优先使用 `action=scan`，在同一可见响应中返回多个条目及其精确片段，JSON 文本不超过3900 B，实际完整 MCP 响应不超过6000 B。以 `nextOffset` 和 `nextCharacterOffset` 续读；独立评审可用 `requiredOnly=true` 批量阅读全部必读条目，历史观察仍可单独检索。哈希与连续完整覆盖检查不变；批量读取在工具审计成功后以一条账本帧登记所有返回片段，不能记录未返回部分。`index/read` 兼容保留，分页大小只控制传输，不限制总读取量。

独立评审必须完整读取必需的用户输入、有效方案、当前候选、变更基线和证据。读取区间须从开头连续覆盖到结尾；只读末页不算完整。finish 与 Provider 终态各自核对同一冻结调用的读取记录；缺页或哈希变化不能返回合格评审。读取证明表示原内容实际通过工具提供，不能证明模型一定理解正确。旧调用保留原记录，不伪装已使用新传输。

- 必需产物齐全、确定性检查与独立评审无阻塞：待批准变更包。
- 需要用户决定：暂停并集中提出最多三题。
- 相同语义草案、问题和证据连续三次无进展：暂停并说明原因。
- 环境、权限、配额或服务错误无法继续：保存成功任务，提供继续或重新运行。
- 用户取消或依据失效：停止后续调度，撤销本轮未批准产物。

取消检查覆盖调用前的异步文件准备；准备期间收到取消后不得启动下一次 Provider 调用。取消完成还须等待已启动调用清理，释放运行与并发槽。

瞬时服务失败重试两次，等待五秒与二十秒；明确的个人订阅额度耗尽（Individual quota reached）保存并立即暂停，不按瞬时故障重复调用。普通 429 限流与连接故障仍按瞬时规则处理。界面显示暂停原因和服务提供的预计恢复时间，未知时间不补造，估计不作为可用保证；用户恢复额度或切换 agy 账号后可显式继续，仍须检查依据。等待提醒不终止有效工作。任务日志与正式方案版本分离；恢复校验依据和结果哈希，已完成任务可以复用，改动或过期产物不能继续应用。SSE 使用事件序号重放。

## 验收

测试验证结构化契约、取舍完整、去重、依赖、来源、审批原子性、取消、恢复、材料完整性、任务与验收关联和开发包哈希。真实 agy 能力与模拟测试分别记录，不能用模拟成功证明真实调用。用户亲自审阅是独立验收项，AI 评审不能代替目标项目的实际开发结果。
