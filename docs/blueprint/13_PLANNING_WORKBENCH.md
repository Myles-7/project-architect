# Project Architect：已批准重构契约

批准日期：2026-10-04。此文档覆盖旧蓝图冲突项；适用于 Project Architect 自身。用户项目约束以其已批准需求为准。

## 产品

个人开发者使用的 AI 项目规划工作台。新项目优先，输入文字、Markdown、PDF、DOCX、截图与设计图；先澄清，再分别生成并批准产品与体验、技术与接口、任务与验收。支持开发反馈的依赖影响分析和局部修订，不承诺理解任意代码库，不监督外部 Coding Agent。

每轮最多三道独立选择题，二至四个有效选项，每项包含做法、优点、缺点、影响和可逆性；解释为什么现在问和推荐理由，不预选提交。自定义答案、委托与暂缓保存原文，不直接确认。已解决主题不重问；重问必须有需求变更原因。

对话与当前方案双栏，草案与正式方案清楚分离，审批相关分组的变更包。首页为想法与材料输入，高级功能放次级入口。真实任务和耗时取代虚构百分比；取消始终可用。准备度用待澄清、待设计、可审阅、包含验证任务、已批准表示，空泛决定数量不是可开发证明。

## 状态与审批

Core 是正式状态唯一权威。AgentTaskResult 只能提出结构化建议；用户批准 ChangeSet 后原子提交蓝图、决定、主题、证据、阶段与审批来源。拒绝或未批准内容保持草案。替代保留历史，Locked 变更须显式解锁。正式写入要求 expectedRevision 和 operationId；重复操作幂等，过期依据不得应用。

新增 PlanningRun、PlanningTask、AgentTaskResult、ChangeSet、BlueprintState、EvidenceRecord、DecisionTopic。蓝图与变更包纳入现有两阶段提交；运行事件与中间产物分离，不因进度改变正式版本。旧项目兼容读取，歧义和误确认记录生成诊断与待批准清理，不自动删除历史。

## agy 运行

PlanningRuntime 根据依赖调度多个登记任务，默认并行四个。设计、研究、验证、整合、独立评审、补证和修订均记录。工作者不能编辑正式状态，不能启动未登记子 Agent。问题集中汇总。允许多次调用，无费用、Token、总调用或修订轮数门禁。

满足完整产物、确定性检查、无评审阻塞时交付；需要用户决策则暂停；相同草案/问题/证据连续三次重复则暂停；无法恢复环境错误、取消或依据变化时停止。瞬时服务错误重试两次（5 秒、20 秒）。一分钟/三分钟仅提醒，不作为有效任务超时。

默认设计/整合 claude-opus-4-6-thinking，研究/视觉/评审 gemini-3.1-pro-high。预检实际模型与能力，高级设置显式覆盖，不自动降档。遵守 headless user event 输入，只采用终态 structured_output；流式日志落盘。材料索引和硬约束始终进入任务，按需读取完整材料，记录来源/日期/哈希/适用范围。

本地 stdio MCP 提供材料读取与受控试验，Docker 只挂载独立试验目录，无正式项目、凭证、用户目录或 Docker socket。Node/Chromium、Python 环境，隔离网络，参数由服务构造。保存代码、环境、日志与结果。未执行、失败或不适用平台永远不能记为通过。

## 接口与交付

GET /api/projects/:id/planning；POST /api/projects/:id/planning/runs；GET run 状态与 events（SSE 序号恢复）；run cancel/resume；POST questions/answers（结构化批量）；变更包 edit/approve/reject；从已批准蓝图本地编译文档。

全项目任务必须含目标、关联需求、依赖、范围和排除、模块/接口/数据、正常/异常行为、验证、完成条件、假设。未验证能力建独立验证任务及依赖。产物完整生成、校验、哈希后发布，不留下成功的半套文档。输出 START_HERE、PROJECT、PRODUCT、USER_FLOWS、UX_UI_SPEC、TECHNICAL_GUIDE、DEVELOPMENT_PLAN、ACCEPTANCE、AGENTS、tasks.json 和 ZIP。保留用户说明区，其他外部修改作为反馈。

## M0–M8 与验收

M0 基线/规范；M1 模板打包/严格失败/决定键/最新批次/无效强度；M2 状态/主题/审批/自由文本；M3 agy/材料/视觉/研究/试验；M4 调度/评审/修订/恢复；M5 三阶段/问题质量/覆盖/局部修订；M6 双栏正式 UI；M7 开发包；M8 迁移/集成/真实能力和用户审阅。

相关测试通过后进入依赖阶段。测试覆盖误确认、语义身份、审批原子性/锁/版本/幂等、并行隔离、失败/取消/重启/过期、实际图片读取、试验隔离、准备度真实性、文档差异/哈希/异 cwd、旧项目副本迁移。Playwright 覆盖实际默认流程。模拟结果不能证明真实 agy 能力。

最终三个场景：模糊想法到全方案、文字+截图、批准后变更关键需求。自动检查后由用户审阅。本轮不要求 Coding Agent 实际实现目标项目；AI 评审不能代替实践结果。

保留 TS/React/Express/文件存储/两阶段提交；Node 24 LTS；依赖 lockfile 固定。禁止本产品数据库、登录、账号、团队权限和云同步。B2.1 仅历史，frontend 原型隔离。新体验通过验收后默认，旧接口仅必要兼容。
