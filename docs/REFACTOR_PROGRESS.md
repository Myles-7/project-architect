## 重要修复

回答续接只排除本轮已处理答案的机械影响，不忽略其他依据变化。未审阅输入与材料不能重新编译旧方案；完整反馈和局部反馈分别维护下游阶段有效性。并行任务等待全部工作者清理，取消可触达兄弟任务；精确相同 kind/goal 补证去重。恢复核对 task ID、result receipt 与输出 hash，不接受外改产物。

明确选择保存 `answerKind=selection` 和原 `selectedOptionKeys`，后续任务收到完整原题以及所选做法、收益、代价、影响和可逆性。历史缺少选择键、损坏或重复键均为 `unknown`，不按标签或推荐反推。旧项目只有明确问题关联才补回 decisionKey；歧义、误确认和未关联有效记录保留并诊断，清理须审批，Locked 须明确解锁。健康旧格式首次读取不写盘，下一正常提交才持久化新结构并保留旧 revision。

tasks.json v2 的 `dependsOn` 只引用导出 task/validation；沿已批准 dependsOn 穿过非任务块，遇首个任务端点停止。原边保留为 `blueprintDependsOn`，非任务引用保留于 `blueprintReferences`。START_HERE、任务数组与开发计划使用一致稳定拓扑。全图缺引用或循环在 staging 前拒绝；不从 requirementIds 补造语义依赖。历史 v1 包保持原字节。

旧 discovery 生产写入口停用，文档生成共用正式蓝图编译器。Windows 启动器固定工作目录、检查 Node24 并构建整个工作区。

最终审查补齐了拒绝启动的写入顺序：阶段门控在 feedback 保存前校验，失败与同请求重试保留输入、问题、版本和文件。块及分组依赖改为共享全图 active/done 检查，保留孤立环、自环和缺引用，避免有效共享前置反复展开。同一张 60 块/85 边图单次测量从 2646.2ms 降至 0.1ms，属于单次合成测量，不能当作稳定耗时承诺。旧清理部分审批后复用当前包；明确拒绝清理表示保留同 ID/同原文，不再反复推送，原文改变或新记录仍需审阅。新增失败→通过回归及最新正式 HTTP 副本验收 49 项记录见验收报告。
