## 快速捕获与标签解析交互流

ID：flow-quick-capture；关联需求：feature-quick-capture；依赖：feature-quick-capture

### 交互流程步骤拆解
1. **步骤 1（捕获唤起）**：
   - 用户打开页面或按下全局按键 `N`，页面平滑滚动至捕获卡片，输入框聚焦并高亮蓝色外发光边框。
2. **步骤 2（文本录入与标签建议）**：
   - 用户输入文字，输入框根据内容长度平滑撑开；
   - 若用户输入 `#` 字符，下方浮出轻量标签自动补全气泡，列出历史高频标签，支持通过上下方向键选择或继续输入创建新标签；
   - 用户亦可直接点击输入框底部的标签推荐胶囊完成附加。
3. **步骤 3（提交触发与校验）**：
   - 用户敲击 `Ctrl/Cmd + Enter` 或点击“记录灵感”按钮；
   - 系统检查输入内容：
     - **正常分支**：文本去除首尾空白后字符数 > 0，执行步骤 4；
     - **异常分支**：内容为空，输入框执行 CSS Shake 抖动动画，光标保留，终止流程。
4. **步骤 4（前端本地写入与视图更新）**：
   - 生成便签数据实体（生成唯一 UUID、记录当前本地时间戳、提取标签数组、收藏状态设为 false、置顶设为 false）；
   - 异步写入本地持久化存储（IndexedDB）；
   - 前端状态流即时将新便签推入列表头部，伴随 200ms 的平滑淡入展开动效；
   - 未备份变更计数器递增 1；
   - 输入框清空，草稿缓存重置，光标继续停留在输入框以便连续输入。
5. **步骤 5（存储异常处理与状态保留）**：
   - 若本地持久化层写入抛出配额超限异常（QuotaExceededError），系统捕获错误，输入框内容完整保留在当前输入区不予清空，不关闭当前界面，顶部弹出琥珀色 Toast 警告：“本地存储容量已满，保存失败，请清理或导出备份”；用户可复制当前内容或点击“立即导出备份”清理空间后重试保存。

## 便签状态流转、回收区 7 天保留与还原清空交互流

ID：flow-note-card-actions；关联需求：feature-note-card-view；依赖：feature-note-card-view

### 交互流程步骤拆解
1. **步骤 1（卡片悬停与操作激活）**：
   - 鼠标移入卡片区域或触控点击，卡片呈现轻微悬浮效果，快捷操作栏显现。
2. **步骤 2（收藏与置顶状态切换）**：
   - 点击星标或图钉图标，150ms 内完成微动效并持久化对应状态；写入失败则动画回滚并提示错误。
3. **步骤 3（归档流转）**：
   - 点击归档按钮，卡片向右侧平滑滑出，侧边栏“已归档”计数 +1，当前视图计数 -1，未备份变更计数递增 1。
4. **步骤 4（移入回收区交互流）**：
   - 用户在活跃便签卡片上点击垃圾桶“删除”图标；
   - 系统将该便签标记为 `status = 'trashed'`, `trashedAt = Date.now()`, `updatedAt = Date.now()`；
   - 异步写入 IndexedDB 持久化存储；
   - 卡片以渐隐动效从活跃视图中移除，侧边栏【回收区】计数 +1，未备份变更计数递增 1；
   - 页面底部弹出 Toast 通知：“便签已移入回收区（保留7天）[查看回收区]”；若写入失败，卡片恢复在列表中展示并提示“移入回收区失败”。
5. **步骤 5（回收区视图交互与便签还原流）**：
   - 用户点击侧边栏【回收区】系统视图；
   - 视图渲染所有 `status === 'trashed'` 的便签列表，每张卡片展示剩余保留天数：`Math.max(0, 7 - Math.floor((Date.now() - trashedAt) / 86400000))`；
   - 用户点击【还原】按钮：
     - 系统将该便签更新为 `status = 'active'`, `trashedAt = null`, `updatedAt = Date.now()`，保留原置顶、收藏与标签属性；
     - 异步持久化成功后，便签从回收区视图移出，侧边栏回收区计数 -1，未备份计数 +1；
     - 底部 Toast 提示：“便签已成功还原至全部灵感”。
6. **步骤 6（超过 7 天过期横幅与彻底清空交互流）**：
   - 依据已确认决策 dec-cd105627-1e53-4251-9f8e-9422bdfbbd5c：
   - 系统检测到存在 `Date.now() - trashedAt > 7 * 86400 * 1000` 的便签时，侧边栏回收区入口点亮琥珀色预警圆点；
   - 用户切换至回收区视图，顶部常驻琥珀色提示横幅“有 X 条便签已超过 7 天保留期限”，提供【清空已过期便签】与【一键彻底清空】两个操作入口；
   - 用户点击任一清理按钮（或卡片上的单条【彻底删除】）：
     - 屏幕居中弹出红色警告模态对话框，清晰告知操作不可撤销；
     - 用户点击对话框中的“确认删除”：系统开启 IndexedDB 事务执行物理物理删除（`db.notes.delete(id)` 或批量删除）；
     - 事务成功提交后，被清理的便签节点从 DOM 移除，回收区徽标更新，未备份变更计数递增 1，过期横幅自动消失或更新数字；
     - 若物理删除事务中途失败，事务自动回滚，便签完好保留在回收区中，弹窗提示“删除失败，请重试”。

## 标签添加、多维组合筛选与重命名交互流

ID：flow-tag-organization；关联需求：feature-tag-organization；依赖：feature-tag-organization

### 交互流程步骤拆解
1. **步骤 1（标签录入与关联）**：用户在捕获或编辑时输入 `#xxx`，系统分词提取并持久化。
2. **步骤 2（侧边栏标签交互与排除回收区）**：
   - 标签管理器监听数据总线，遍历非回收区便签派生出当前标签统计字典；
   - 用户单击标签切换单选过滤，再次单击取消；
   - 当用户在工作区删除便签时，便签进入回收区，派生计算自动剔除该便签标签，侧边栏标签数字即时响应。
3. **步骤 3（多标签组合过滤）**：按住 `Ctrl` 键点击多个标签，执行交集严格匹配。
4. **步骤 4（标签重命名交互）**：
   - 用户选择重命名并输入新名称；
   - 系统开启读写事务，批量更新活跃、归档及回收区便签中的该标签；
   - 事务成功则热更新视图，若事务中断则整体回滚保留原状。

## 即时检索、动态高亮与快捷清除交互流

ID：flow-search-filter；关联需求：feature-search-filter；依赖：feature-search-filter

### 交互流程步骤拆解
1. **步骤 1（搜索激活）**：用户按下 `/` 键或点击搜索栏，搜索栏激活外发光。
2. **步骤 2（按键键入与作用域过滤）**：
   - 用户输入查询词；
   - 80ms 防抖后触发搜索；
   - 检索引擎根据当前视图判断作用域：若处于常规视图，从内存活跃/归档集合中过滤；若处于回收区视图，从回收区暂存集合中过滤；
   - 匹配结果生成黄色高亮标记并更新视图。
3. **步骤 3（无匹配边界展示）**：无匹配时展示无结果占位状态及一键清空按钮。
4. **步骤 4（退出检索）**：点击 `×` 或按 `Esc`，清空搜索词，视图恢复。

## 详情浏览、Markdown 解析与编辑保存交互流

ID：flow-note-detail-edit；关联需求：feature-note-detail-edit；依赖：feature-note-detail-edit

### 交互流程步骤拆解
1. **步骤 1（弹窗打开与状态感知）**：
   - 用户点击卡片主体；
   - 模态弹窗展开；系统检查便签 `status`：
     - 若 `status === 'trashed'`：展示回收区只读提示栏，禁用 Todo 复选框交互与编辑切换，展示【还原】与【彻底删除】按钮；
     - 若 `status === 'active' | 'archived'`：正常提供阅读/编辑模式切换。
2. **步骤 2（交互与阅读）**：阅读模式下点击代码复制调用 Clipboard API。
3. **步骤 3（切入编辑模式）**：非回收区便签点击编辑进入等宽文本区修改内容。
4. **步骤 4（保存与异常分支）**：按 `Ctrl+S` 保存；写入失败则弹窗保持开启，草稿完整保留，提示重试。
5. **步骤 5（回收区弹窗操作分支）**：
   - 点击【还原】：执行还原逻辑，便签恢复为 active，提示条消失并允许直接编辑；
   - 点击【彻底删除】：弹出二次确认，用户确认后彻底物理删除便签并关闭弹窗。

## 数据备份导出、导入恢复、回收区处理与防丢提醒交互流

ID：flow-data-portability；关联需求：feature-data-portability；依赖：feature-data-portability

### 交互流程步骤拆解
1. **步骤 0（变更追踪与温和提醒激活）**：便签新增、编辑、移入回收区、还原或删除时递增 `unbackedChangesCount`；超 20 条或超 7 天时侧边栏底部点亮琥珀色提示点与“立即导出”按钮。
2. **步骤 1（唤出数据备份面板）**：用户点击顶部导航栏右侧的“设置/数据”图标，弹出“数据管理与本地备份”弹窗面板。
3. **步骤 2（导出交互流 - 包含回收区策略）**：
   - 界面展示导出选项，提供【包含回收区便签】复选框（依据决策 `product.backup_trash_inclusion_policy`，默认处于勾选状态）；
   - 用户点击“导出全量 JSON 备份”；
   - 系统异步读取便签，按设置过滤，生成符合 Schema v1 的 JSON 字符串并触发下载；
   - 成功后提示“备份文件已成功导出”，重置 `unbackedChangesCount = 0`，更新 `lastBackupAt = Date.now()`，侧边栏提醒点复位；若触发失败保持面板并提示重试。
4. **步骤 3（导入交互与格式校验流）**：
   - 用户拖入或选择 `.json` 文件；
   - 系统执行 Schema 校验，检验单条便签的 `status` 与 `trashedAt` 结构；校验失败明确弹窗报错，本地数据保持不变；校验通过展示便签统计数与合并/覆盖选项。
5. **步骤 4（写入合并与超期便签即时警示）**：
   - 用户选择“智能增量合并”确认；
   - 事务逐条比对写入，保留回收区便签的 `trashedAt` 时间戳；
   - 事务提交后，系统立即执行超期检测：若导入的回收区便签存在驻留超 7 天记录，左侧边栏【回收区】入口即刻点亮琥珀色过期预警圆点，回收区顶部展示常驻过期横幅；
   - 弹出通知：“数据导入完成：新增 X 条，更新 Y 条”；若事务中断则整体回滚至导入前状态。
