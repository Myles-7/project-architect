## 秒级随手灵感极速捕获功能

ID：feature-quick-capture；关联需求：block-scope-core-boundaries；依赖：page-main-workspace

### 功能定义与交互规范
1. **自动聚焦与极速唤起**：
   - 用户打开应用时，光标默认聚焦于输入框；若页面处于非输入焦点状态，按下快捷键 `N` 立即滚动至顶部并聚焦输入框。
2. **自适应高度与多行排版**：
   - 默认高度为单行输入框（占位提示：“随手记下新灵感... 按 Ctrl+Enter 保存，输入 #添加标签”）。
   - 随输入行数增加，输入框平滑向上/向下展开至最多 8 行高度，超出后出现内部平滑滚动条。
3. **快捷键提交与提交防抖**：
   - 支持键盘 `Ctrl + Enter` (Windows/Linux) 或 `Cmd + Enter` (macOS) 触发瞬时提交。
   - 点击右下角“记录”按钮亦可提交。提交后输入框清空并恢复单行初始状态。
4. **智能行内标签提取**：
   - 支持在正文任意位置输入 `#标签名`（如 `#React 探究并发渲染特性`）。
   - 提交时自动通过正则匹配提取标签名并归并至便签标签属性中，正文可保留完整语义。
   - 输入框下方同时提供最近使用的快捷标签胶囊，点击即可一键附加到当前便签。
5. **边界条件与失败回退保护**：
   - 禁止提交仅含空格或换行符的无效内容。内容为空时“记录”按钮置灰禁用；强制按快捷键时输入框执行左右轻微抖动动画，内容完整保留。
   - 若本地 IndexedDB 写入异常（如存储空间不足 QuotaExceededError），输入卡片坚决不关闭，输入框内的文本与标签完整保留，界面弹出明确错误提示：“保存失败：本地存储已满，请导出备份或清理空间”，用户可在复制文本或清理空间后重新点击保存。

### 验收标准（Given / When / Then）
- **场景 1：快捷键常规提交**
  - **Given** 用户在工作区页面，
  - **When** 用户在捕获输入框键入“验证 Vite 静态构建输出 #前端”，并按下 `Ctrl + Enter`，
  - **Then** 输入框瞬间清空并收缩为单行，便签流顶部以淡入下移动画立即插入该卡片，包含正文与 `#前端` 标签，对应本地数据即刻持久化。
- **场景 2：空文本校验拦截**
  - **Given** 捕获输入框无内容或仅有换行空格，
  - **When** 用户尝试点击“记录”或按下 `Cmd + Enter`，
  - **Then** 提交动作被拦截，输入框外边框出现红色警示抖动，列表不增加任何卡片，焦点保留在输入框。
- **场景 3：存储写入失败保护**
  - **Given** 浏览器处于极端配额满状态，
  - **When** 用户键入灵感并尝试提交，
  - **Then** 捕获失败，输入框内容完整保留不被清空，卡片不关闭，弹出错误 Toast，提供重试与导出入口。

## 便签流多视图展示、生命周期流转与回收区保留功能

ID：feature-note-card-view；关联需求：block-scope-core-boundaries；依赖：page-main-workspace

### 功能定义与交互规范
1. **双布局形态自适应**：
   - 瀑布流卡片视图（Card Grid）与紧凑列表视图（Compact List）无缝切换，偏好保存在本地存储中。
2. **多维生命周期状态管理**：
   - **置顶（Pinned）**：卡片固定在列表首部独立“置顶灵感”分类区域，右上角显示高亮图钉标识。
   - **收藏（Favorited）**：卡片提供星标按钮，点击即可加入“已收藏”快捷视图。
   - **归档（Archived）**：点击“归档”移出常规视图，可在“归档箱”中找回。
   - **回收区暂存（Trashed）与 7 天保留流转**：
     - 点击删除图标，便签不直接销毁，而是移入回收区，状态更新为 `status='trashed'`，记录时间戳 `trashedAt = Date.now()`。
     - 卡片从活跃便签流中移除，侧边栏【回收区】计数 +1，未备份变更计数 +1；界面底部弹出轻量 Toast 通知：“便签已移入回收区（保留7天）[查看回收区]”。
     - 进入回收区视图后，每条便签展示当前已在回收区天数及剩余保留天数（如“还剩 5 天”），提供【还原】与【彻底删除】按钮。
     - **一键还原**：点击【还原】，便签状态恢复为 `status='active'`，`trashedAt = null`，原标签、置顶及收藏状态完好保留，重新插入活跃便签流，回收区计数 -1。
     - **超期提示与永久清理（依据 dec-cd105627-1e53-4251-9f8e-9422bdfbbd5c）**：
       - 当便签在回收区驻留满足 `Date.now() - trashedAt > 7 * 86400 * 1000` 时，侧边栏【回收区】入口显示琥珀色预警圆点。
       - 用户进入回收区时，顶部常驻琥珀色提示横幅“有 X 条便签已超过 7 天保留期限”，提供【清空已过期便签】与【一键彻底清空】按钮。
       - 单条点击【彻底删除】或点击清空按钮时，强制弹出模态二次确认对话框，防止误触；经用户明确确认后，从本地存储中执行物理永久删除。
3. **失败处理与状态保留机制**：
   - 若置顶、收藏、归档、移入回收区或还原操作在持久化层写入失败，卡片状态立刻回滚至操作前状态，并弹出 Toast 提示“操作未能保存至本地，已恢复原状”，便签内容完整保留在内存与界面中。
   - 若清空回收区或单条彻底删除事务执行异常，底层事务自动完整回滚，便签继续安全保留在回收区中，弹窗提示失败并建议用户重试。

### 验收标准（Given / When / Then）
- **场景 1：置顶与排序即时生效**
  - **Given** 列表中存在多条便签，
  - **When** 用户点击某中间位置便签的图钉按钮，
  - **Then** 该便签立刻平滑升至“置顶区域”首位，图钉图标由轮廓线变为实心高亮状态。
- **场景 2：删除便签移入回收区并展示 7 天保留**
  - **Given** 用户在卡片上点击“删除”图标，
  - **When** 卡片从当前活跃流淡出，
  - **Then** 底部弹出“便签已移入回收区（保留7天）”提示，侧边栏【回收区】计数 +1；用户切换至回收区视图可查看该便签，卡片显示“还剩 7 天”保留状态。
- **场景 3：回收区便签一键还原**
  - **Given** 回收区中存在一条原打有 `#前端` 标签并置顶的便签，
  - **When** 用户在回收区视图点击该便签卡片上的【还原】按钮，
  - **Then** 便签从回收区移除，侧边栏【全部灵感】与【置顶灵感】中即刻恢复该便签，`#前端` 标签与置顶状态完好保留。
- **场景 4：超过 7 天常驻横幅与二次确认彻底清空**
  - **Given** 回收区中有便签的移入时间超过 7 天（> 168 小时），
  - **When** 用户切换至回收区视图，
  - **Then** 顶部常驻显示琥珀色提示横幅“有 X 条便签已超过 7 天保留期限”；用户点击【清空已过期便签】后弹出二次确认对话框，点击确认后该批超期便签被物理永久删除，未超期便签完好保留。
- **场景 5：持久化失败回滚保护**
  - **Given** 数据库处于极端锁死或模拟只读异常，
  - **When** 用户尝试执行移入回收区或还原，
  - **Then** 界面弹出“操作失败，已恢复原状”，卡片在原列表中恢复显示，数据完整无损。

## 多维灵活标签与分类过滤功能（排除回收区便签）

ID：feature-tag-organization；关联需求：block-scope-core-boundaries；依赖：page-main-workspace

### 功能定义与交互规范
1. **便签多标签支持与格式规范**：
   - 单条便签支持关联 0 到多个标签，标签名支持中英文、数字及连字符，长度限制为 1 到 20 字符。
2. **全局标签池聚合与统计（排除回收区便签）**：
   - 侧边栏“标签”面板自动遍历全部活跃（active）与归档（archived）便签，汇总所有独立标签并按关联便签数降序排列（如 `#灵感 (15)`、`#前端 (8)`）。
   - **严格排除回收区便签**：处于回收区（`status === 'trashed'`）的便签所附带的标签不计入侧边栏标签统计数；当便签被移入回收区时，关联标签的计数即时扣减；若该标签下所有便签均在回收区中，该标签在侧边栏自动隐藏，彻底避免已删除便签污染正常标签池。
   - 当便签从回收区一键还原时，其关联标签统计数无缝恢复加回。
3. **单选与多选交集组合过滤**：
   - 单击标签激活过滤；`Ctrl/Cmd` + 单击多个标签开启多标签交集（AND）过滤，仅展示同时包含所有选中标签的活跃/归档便签。
4. **标签全局重命名与批量更新失败保护**：
   - 鼠标悬停提供“编辑”重命名功能，在事务中批量更新所有包含该标签的便签（同时更新回收区便签中的该标签名称，确保便签还原后标签名称一致）。
   - 批量写入若遇配额超限或中断，底层事务自动回滚，原有标签完整保留不损坏。

### 验收标准（Given / When / Then）
- **场景 1：标签单选过滤**
  - **Given** 侧边栏存在 `#工具推荐 (5)` 标签，
  - **When** 用户点击该标签，
  - **Then** 便签流立即刷新，仅显示打有 `#工具推荐` 的 5 条活跃卡片。
- **场景 2：便签移入回收区后标签统计扣减**
  - **Given** `#前端` 标签关联了 3 条便签，
  - **When** 用户将其中的 1 条便签移入回收区，
  - **Then** 侧边栏 `#前端` 标签的计数毫秒级变为 `(2)`；若用户在回收区将该便签还原，计数即刻恢复为 `(3)`。
- **场景 3：标签批量重命名事务一致性与回滚**
  - **Given** 系统中有打有 `#old-tag` 的便签（含活跃与回收区便签），
  - **When** 用户发起重命名为 `#new-tag`，
  - **Then** 事务提交后所有关联便签同步更新；若事务遭遇模拟中断，事务完整回滚，原标签不变。

## 即时全文模糊检索与关键词高亮功能（回收区隔离机制）

ID：feature-search-filter；关联需求：block-scope-core-boundaries；依赖：page-main-workspace

### 功能定义与交互规范
1. **即时无延迟响应与输入防抖（待验证目标）**：
   - 顶部搜索框键入时设置 80ms 轻度防抖，在 1,000 条便签基准下检索端到端响应时间目标小于 150ms。
   - 检索范围覆盖：正文纯文本、标签名称、创建时间等元信息。
2. **关键词动态高亮渲染**：
   - 命中的关键词文本自动被微黄色背景的 `<mark class="highlight">` 标签包裹高亮呈现。
3. **全局检索与回收区范围隔离规范**：
   - **主工作区常规检索**：当处于【全部灵感】、【已收藏】或【已归档】系统视图时，搜索范围严格限定为活跃与归档便签，**自动排除回收区（status='trashed'）便签**，避免已删除内容干扰正常搜索结果。
   - **回收区内限定检索**：当用户切换至【回收区】系统视图时，顶部搜索框的作用域自动切换为仅在回收区内部进行检索，便于用户在大量待清理便签中精准定位需要还原的特定灵感。
4. **快捷键唤醒与快捷重置**：
   - 敲击键盘斜杠键 `/` 快速聚焦搜索框；点击 `×` 或按下 `Escape` 立即清空搜索输入并恢复未过滤列表。
5. **特殊字符转义与防崩保护**：
   - 输入连续正则特殊符号时安全转义，无匹配时展示清晰空状态引导。

### 验收标准（Given / When / Then）
- **场景 1：关键词即时搜索与高亮**
  - **Given** 列表中存在包含“IndexedDB 持久化方案”的活跃便签，
  - **When** 用户在搜索框键入 `indexeddb`，
  - **Then** 列表仅保留匹配卡片，卡片正文中对应的 `IndexedDB` 词段呈现高亮背景。
- **场景 2：回收区便签隔离于常规检索**
  - **Given** 某便签包含关键词“季度总结”且已移入回收区，另有一条活跃便签也包含“季度总结”，
  - **When** 用户在【全部灵感】视图搜索“季度总结”，
  - **Then** 搜索结果仅展示该活跃便签，回收区便签被严格隔离过滤不显示。
- **场景 3：回收区内部搜索**
  - **Given** 用户切换至【回收区】系统视图，
  - **When** 用户在搜索框键入“季度总结”，
  - **Then** 搜索结果精准列出处于回收区中的该便签，并高亮关键词，支持直接点击【还原】。
- **场景 4：快捷键清除与特殊符号转义**
  - **Given** 用户输入正则符号并处于过滤态，
  - **When** 用户按下 `Esc`，
  - **Then** 搜索框文本清空并失焦，便签流平滑恢复全量显示。

## 便签详情模态展示与 Markdown 实时编辑功能（回收区只读保护）

ID：feature-note-detail-edit；关联需求：block-scope-core-boundaries；依赖：page-main-workspace

### 功能定义与交互规范
1. **沉浸式模态详情窗口**：点击卡片正文平滑居中弹出，支持键盘 `Esc` 快捷关闭。
2. **轻量 Markdown 排版解析与代码语法高亮**：
   - 支持标题、列表、GFM 任务清单（复选框可勾选）、代码块着色、外链安全防跳（`rel="noopener noreferrer"`）。
   - 代码块右上角浮动一键复制按钮。
3. **回收区便签只读保护规范**：
   - 当用户从【回收区】视图中点击某张处于回收区的便签时，详情模态弹窗强制以【只读预览模式】打开，禁用编辑切换与待办清单勾选；
   - 弹窗顶部固定呈现警示提示栏：“此便签处于回收区，不可直接编辑。请先【还原】后再行修改，或点击【彻底删除】物理清理”；
   - 弹窗右上角提供【还原便签】与【彻底删除】快捷按钮，点击【还原】即刻触发还原并切入正常可编辑态，点击【彻底删除】弹出二次确认弹窗。
4. **常规便签编辑与保存失败保护**：
   - 非回收区便签支持“编辑/预览”切换及 `Ctrl/Cmd + S` 快捷保存；
   - 若本地持久化层写入抛出配额或数据库异常，弹窗绝对不关闭，正在编辑的文本草稿完整保留在编辑域中，顶部展示红色错误提示与“重试保存”按钮，确保编辑内容零丢失。

### 验收标准（Given / When / Then）
- **场景 1：Markdown 格式化排版与外部链接安全防跳**
  - **Given** 某便签包含多级标题与外链，
  - **When** 用户点击进入详情弹窗，
  - **Then** 正文清晰排版，外链在新标签页安全打开。
- **场景 2：回收区便签只读保护与还原入口**
  - **Given** 用户在回收区视图点击一条便签卡片，
  - **When** 详情模态弹窗打开，
  - **Then** 弹窗顶部显示黄色警示条提示“处于回收区不可编辑”，输入框禁用，弹窗提供【还原便签】与【彻底删除】按钮。
- **场景 3：常规编辑保存失败草稿保留**
  - **Given** 用户在编辑弹窗修改了灵感长文，
  - **When** 点击保存但在写入时抛出配额异常，
  - **Then** 详情弹窗维持开启不关闭，已修改草稿完整保留在文本框中，界面展示错误警告并保留重试按钮。

## 本地数据备份导出、恢复、回收区策略与温和防丢提醒功能

ID：feature-data-portability；关联需求：block-scope-core-boundaries；依赖：page-main-workspace

### 功能定义与交互规范
1. **一键全量导出为结构化 JSON 备份（包含回收区便签与排除选项）**：
   - 依据决策 `product.backup_trash_inclusion_policy`，支持将当前本地保存的所有便签数据一键打包导出为符合标准规范的 JSON 文件。
   - **默认策略与可控排除**：默认导出包含处于回收区（`status === 'trashed'`）的便签，完整保留其 `trashedAt` 移入时间戳与关联标签；同时在数据管理面板的导出设置中提供【排除回收区便签】复选框，允许用户按需仅导出活跃与归档便签。
   - 导出的文件名遵循规则：`spark-notes-backup-YYYY-MM-DD.json`。
2. **Markdown 格式导出支持**：
   - 支持将所有活跃与归档便签批量导出为整理好的 Markdown 汇总文件或压缩包，标签转换为 YAML FrontMatter。处于回收区的便签默认不混入正常 Markdown 导出中。
3. **安全数据导入与冲突消解**：
   - 提供拖拽上传与文件选择器导入外部 JSON 备份文件。
   - **格式强校验**：严格校验 `schemaVersion`、`notes` 数组及单条记录必填字段（包含 `status` 与 `trashedAt` 校验）；校验失败坚决拦截报错，不触碰本地任何既有数据。
   - **智能增量合并与超期便签即时警示**：
     - 比对 ID 与 `updatedAt` 时间戳进行合并更新；
     - 若导入的便签处于回收区（`status === 'trashed'`），完整还原其 `trashedAt` 时间戳；
     - **超期即时感知**：若导入的回收区便签中存在已超过 7 天保留期限的记录（`Date.now() - trashedAt > 7 * 86400 * 1000`），导入事务提交后立即激活左侧边栏【回收区】入口的琥珀色过期预警圆点，并在用户切入回收区时展示常驻过期横幅，提醒用户及时清理。
     - **全量覆盖恢复**：清空前先自动生成临时内存快照，若覆盖写入发生异常立即利用快照安全回滚，旧数据不丢失。
4. **温和防丢备份提醒（依据决策 dec-b17f49d8-86c3-4a74-baee-856b5d753129）**：
   - 本地元数据记录 `lastBackupAt` 与 `unbackedChangesCount`。便签的新增、编辑、归档、移入回收区、还原及彻底删除均自增计数 1。
   - 累计达到 20 条变更或超过 7 天未备份时，侧边栏底部温和点亮琥珀色提示圆点，展示微文案“有未备份灵感 [立即导出]”，非侵入、不打断。
5. **失败处理与操作保护**：
   - 导出生成 Blob 或下载受阻时保持面板，提示重试，数据完好保留。
   - 导入解析或写入中断时事务自动回滚，本地数据保持导入前状态不变。提供键入 `CLEAR` 确认的清空所有数据高级选项。

### 验收标准（Given / When / Then）
- **场景 1：JSON 备份默认导出包含回收区便签及排除选项**
  - **Given** 本地数据库存有 20 条活跃便签与 5 条处于回收区的便签，
  - **When** 用户在数据面板点击“导出 JSON 备份”（保持默认勾选“包含回收区便签”），
  - **Then** 导出的 JSON 文件中完整包含 25 条便签记录，其中 5 条带有 `status: 'trashed'` 与有效的 `trashedAt` 时间戳；若用户取消勾选该项后导出，文件中仅包含 20 条活跃便签。
- **场景 2：非法格式导入拦截与数据安全**
  - **Given** 用户上传了一份损坏的非 JSON 文本或缺少关键字段的文件，
  - **When** 系统执行文件读取校验，
  - **Then** 弹窗提示“导入失败：文件格式不符合规范”，底层存储拦截阻断，本地现有便签数据完整无损。
- **场景 3：增量合并恢复与超期回收便签即时警示触发**
  - **Given** 导入的备份文件中包含 2 条在 10 天前被移入回收区的便签，
  - **When** 用户执行智能增量合并导入并成功提交，
  - **Then** 导入完成提示成功，主工作区侧边栏【回收区】入口立即点亮琥珀色过期预警圆点；用户切入回收区视图，顶部常驻琥珀色横幅醒目提示“有 2 条便签已超过 7 天保留期限”。
- **场景 4：累计20条变更温和防丢提醒与导出清零**
  - **Given** 用户累计执行了 20 次便签新增、编辑或移入回收区操作，
  - **When** 达到第 20 次操作完成时，
  - **Then** 侧边栏底部温和点亮琥珀色小圆点并展示微文案“有未备份灵感 [立即导出]”；点击“立即导出”后直接触发下载并将提示点复位。
