## 快速捕获与标签解析交互流

ID：flow-quick-capture；关联需求：feature-quick-capture；依赖：feature-quick-capture

### 交互流程步骤拆解
1. **步骤 1（捕获唤起）**：
   - 用户打开页面或按下全局按键 `N`，页面平滑滚动至捕获卡片，输入框聚焦并高亮蓝色外发光边框。
2. **步骤 2（文本录入与标签建议）**：
   - 用户输入文字，输入框根据内容长度平滑撑开；
   - 若用户输入 `#` 字符，下方浮出轻量标签自动补全气泡，列出历史高频标签，支持通过上下方向键选择或继续输入创建新标签；
   - 用户亦可直接点击输入框底部的标签推荐胶囊完成附加。
3. **步骤 3（提交触发与校验）**：
   - 用户敲击 `Ctrl/Cmd + Enter` 或点击“记录灵感”按钮；
   - 系统检查输入内容：
     - **正常分支**：文本去除首尾空白后字符数 > 0，执行步骤 4；
     - **异常分支**：内容为空，输入框执行 CSS Shake 抖动动画，光标保留，终止流程。
4. **步骤 4（前端本地写入与视图更新）**：
   - 生成便签数据实体（生成唯一 UUID、记录当前本地时间戳、提取标签数组、收藏状态设为 false、置顶设为 false）；
   - 异步写入本地持久化存储（IndexedDB）；
   - 前端状态流即时将新便签推入列表头部，伴随 200ms 的平滑淡入展开动效；
   - 未备份变更计数器递增 1；
   - 输入框清空，草稿缓存重置，光标继续停留在输入框以便连续输入。
5. **步骤 5（存储异常处理与状态保留）**：
   - 若本地持久化层写入抛出配额超限异常（QuotaExceededError），系统捕获错误，输入框内容完整保留在当前输入区不予清空，不关闭当前界面，顶部弹出琥珀色 Toast 警告：“本地存储容量已满，保存失败，请清理或导出备份”；用户可复制当前内容或点击“立即导出备份”清理空间后重试保存。

## 便签状态流转与操作撤销交互流

ID：flow-note-card-actions；关联需求：feature-note-card-view；依赖：feature-note-card-view

### 交互流程步骤拆解
1. **步骤 1（卡片悬停与操作激活）**：
   - 用户鼠标移入卡片区域或移动端轻触卡片，卡片呈现轻度阴影悬浮（Elevation）效果，右上角及底部的快捷操作栏渐变显现。
2. **步骤 2（收藏与置顶状态切换）**：
   - 用户点击“星标”图标：图标在 150ms 内完成缩放动画并转为金色高亮，更新内存及本地存储中的 `favorite: true` 字段；
   - 用户点击“图钉”图标：触发列表重新布局动效，置顶便签被归类至首部 pinned 容器，其他卡片执行 CSS Grid 重排；
   - 若写入存储抛错，图标动画回滚，提示“状态更新失败”。
3. **步骤 3（归档流转）**：
   - 用户点击“归档”按钮，卡片向右侧平滑滑出并淡出；
   - 侧边栏“已归档”计数 +1，当前视图计数 -1；未备份变更计数递增 1；
   - 底部出现 Toast：“便签已归档”，提供“撤销”操作链接。
4. **步骤 4（删除与防误触撤销）**：
   - 用户点击垃圾桶删除图标，卡片以缩小渐隐动效从 DOM 中移除；
   - 本地数据标记为软删除状态，开启 5 秒倒计时计时器；
   - 底部通知栏显示“便签已移除 [撤销]”：
     - 若用户点击“撤销”，倒计时中断，便签数据恢复为活跃状态，卡片在原列表位置平滑插回；
     - 若 5 秒倒计时结束无撤销操作，便签正式完成持久化软删除，未备份变更计数递增 1；
     - 若持久化软删除出现数据库异常，界面弹出“删除同步失败，已恢复显示”，便签回退至活跃列表，不丢弃数据。

## 标签添加、多维组合筛选与重命名交互流

ID：flow-tag-organization；关联需求：feature-tag-organization；依赖：feature-tag-organization

### 交互流程步骤拆解
1. **步骤 1（标签录入与关联）**：
   - 用户在快速捕获框或编辑弹窗中输入 `#xxx`，系统实时分词提取，将标签与当前便签绑定并写入存储。
2. **步骤 2（侧边栏标签交互）**：
   - 用户鼠标点击侧边栏的某一标签项；
   - 状态管理器更新当前活动筛选条件数组 `activeTags: ['xxx']`；
   - 主列表组件响应状态变更，应用谓词过滤规则；
   - 卡片流以渐隐淡入动效呈现匹配结果，非匹配卡片退出视口；
   - 若用户再次点击该选中标签，取消该标签过滤并恢复全部视图。
3. **步骤 3（多标签组合过滤）**：
   - 用户按住 `Ctrl` 键点击第二个标签，活动筛选数组变更为 `['xxx', 'yyy']`；
   - 列表应用 `note.tags.includes('xxx') && note.tags.includes('yyy')` 严格匹配；
   - 若过滤结果为 0 条，主视图展示友好空提示：“暂无同时包含 #xxx 与 #yyy 的灵感便签”，附带“移除条件”按钮。
4. **步骤 4（标签重命名交互）**：
   - 用户点击侧边栏标签旁边的三点菜单，选择“重命名”；
   - 弹出就地输入框，用户输入新名称并按回车；
   - 系统检查是否与现有其他标签重名：
     - 若无重名：开启数据库读写事务，遍历更新包含该标签的所有便签并持久化；
     - 若与现有标签重名：弹出轻量确认提示“已存在同名标签，是否将两组便签合并？”，用户确认后执行批量合并；
     - 若事务执行失败：回滚全部修改，保留原标签，提示“更新失败，请重试”。

## 即时检索、动态高亮与快捷清除交互流

ID：flow-search-filter；关联需求：feature-search-filter；依赖：feature-search-filter

### 交互流程步骤拆解
1. **步骤 1（搜索激活）**：
   - 用户在页面按下 `/` 键或鼠标点击顶部搜索栏，搜索栏外圈显现动态焦点光晕，占位符文字变为“输入关键字或 #标签 进行搜索...”。
2. **步骤 2（按键键入与流式过滤）**：
   - 用户键入查询词（如 `React`）；
   - 防抖定时器触发，搜索模块对当前活动便签集合执行过滤比对；
   - 匹配便签集合更新至视图模型，非匹配便签移出 DOM；
   - 正文渲染器对命中词汇进行正则安全转义与拆分，插入高亮标记。
3. **步骤 3（无匹配边界展示）**：
   - 若查询词未匹配到任何便签，内容区呈现无结果占位状态：“未找到与 ‘xxx’ 匹配的灵感”；
   - 占位区提供“清除搜索内容”与“新建包含该词的便签”两个快捷动作。
4. **步骤 4（退出检索）**：
   - 用户点击搜索栏右侧的 `×` 按钮或键盘敲击 `Esc`；
   - 搜索词清空，高亮样式卸载，全量卡片重新以淡入形式恢复展示，滚动位置保持自然。

## 详情浏览、Markdown 解析与编辑保存交互流

ID：flow-note-detail-edit；关联需求：feature-note-detail-edit；依赖：feature-note-detail-edit

### 交互流程步骤拆解
1. **步骤 1（弹窗打开与渲染）**：
   - 用户点击卡片主体，触发点击事件（避开收藏与删除按钮区域）；
   - 模态弹窗以 200ms 缩放淡入动效居中展开，页面主体背景增加毛玻璃遮罩；
   - 默认进入【阅读预览】模式，Markdown 引擎完成 AST 解析并安全渲染为富排版 HTML。
2. **步骤 2（交互与阅读）**：
   - 用户滚动阅读长文，点击代码块“复制”按钮调用 Clipboard API 并触发操作反馈；
   - 用户点击可交互的 Todo Checkbox，状态即时翻转并触发轻量本地存储更新。
3. **步骤 3（切入编辑模式）**：
   - 用户点击顶部“编辑”按钮或双击内容区域；
   - 视图平滑切换为全宽文本编辑框，光标自动定位，文本框保持用户输入焦点；
   - 用户编辑正文文本或修改 `#标签`。
4. **步骤 4（保存与关闭退出分支）**：
   - 用户按下 `Ctrl/Cmd + S` 或点击“完成”按钮：
     - 若保存成功：弹窗平滑退出，主页面卡片摘要同步刷新，未备份变更计数递增 1；
     - 若保存失败（如存储超限）：弹窗保持打开，输入内容完整保留，顶部显示错误提示并提供重试按钮。
   - 用户点击右上角 `×`、点击遮罩或按 `Escape` 键退出：
     - 若无未保存修改：直接退出；
     - 若有未手动保存的改动：系统尝试后台自动保存并提示“修改已自动保存”；若自动保存失败，拦截关闭动作，保持弹窗并提示错误，确保用户输入不被丢弃。

## 数据备份导出、导入恢复与防丢提醒交互流

ID：flow-data-portability；关联需求：feature-data-portability；依赖：feature-data-portability

### 交互流程步骤拆解
1. **步骤 0（变更追踪与温和提醒激活）**：
   - 用户进行灵感记录、内容编辑、标签变更、归档或删除操作时，系统自动递增 `unbackedChangesCount`；
   - 页面加载或状态变更时评估：若 `unbackedChangesCount >= 20` 或 `Date.now() - lastBackupAt > 7 * 86400 * 1000`，侧边栏底部点亮琥珀色提示点与“有未备份灵感 [立即导出]”快捷按钮；
   - 若用户点击快捷按钮，直接跳转执行步骤 2，省去繁琐打开面板路径。
2. **步骤 1（唤出数据备份面板）**：
   - 用户亦可随时点击顶部导航栏右侧的“设置/数据”图标，屏幕弹出“数据管理与本地备份”弹窗面板。
3. **步骤 2（导出交互流）**：
   - 用户点击“导出全量 JSON 备份”按钮；
   - 系统从本地数据库异步读取全部数据实体，构造包含 `version: 1` 与 `exportedAt` 的 JSON 字符串；
   - 系统生成临时 `Blob` 对象并借助虚拟 `<a>` 标签触发浏览器下载：
     - 若触发成功：页面弹出绿色 Toast 提示“备份文件已成功导出”，重置 `unbackedChangesCount = 0`，更新 `lastBackupAt = Date.now()`，侧边栏提醒点复位；
     - 若触发失败：弹窗保持开启，显示“下载触发受限，请检查浏览器下载权限”，数据不发生变动。
4. **步骤 3（导入交互与格式校验流）**：
   - 用户将本地 `.json` 文件拖入虚线上传框，或点击“选择文件”；
   - 前端通过 FileReader API 或 `File.text()` 读取文件文本，并尝试 `JSON.parse` 与 Schema 校验：
     - **异常分支（文件损坏或格式不匹配）**：解析失败或缺少关键字段，弹窗显示红色错误：“文件无法识别，请确保上传由本工具导出的有效备份文件”，流程终止，本地数据完整保持不变；
     - **正常分支（校验通过）**：系统解析出备份中包含便签数量，界面展示导入选项：【智能增量合并】与【全量覆盖恢复】。
5. **步骤 4（写入合并与视图同步）**：
   - 用户选择“智能增量合并”并点击确认；
   - 系统开启数据库读写事务，逐条比对便签主键：
     - 若 ID 不存在：插入新记录；
     - 若 ID 已存在：对比 `updatedAt` 时间戳，保留较新的记录版本；
   - 事务成功提交后，主界面便签流与标签列表执行热重载，展示合并后的最新结果，弹出成功通知：“数据导入完成：新增 X 条，更新 Y 条”；
   - 若事务中途因配额中断抛错：事务自动回滚，本地数据恢复至导入前状态，界面提示“导入中断，已安全回滚至导入前状态”。
